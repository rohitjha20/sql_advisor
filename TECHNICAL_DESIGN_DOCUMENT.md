## 1. Executive Summary

The Azure SQL Server Recommendation Engine is a **Databricks-native, two-notebook pipeline** that:

1. **Collects** 42 metrics from Azure SQL Database via JDBC (2 incremental + 40 snapshot)
2. **Analyzes** telemetry across **10 categories** with **50+ sub-checks**
3. **Scores/Ranks** recommendations using severity × category-weight × impact
4. **Outputs** partitioned Parquet + HTML executive report to ADLS Gen2

### Architecture Principles

| Principle | Implementation |
|---|---|
| **No Delta Tables** | All persistence is Parquet/JSON on ADLS Gen2 |
| **No .py files** (except config) | All logic lives in Databricks notebooks |
| **Single config source of truth** | `config.py` contains all queries, thresholds, pricing |
| **Incremental extraction** | Watermark-based for time-series DMVs |
| **Pure PySpark** | All analysis runs in-cluster — no external dependencies |

## 7. Scoring Algorithm

### 7.1 Priority Score Formula

```
priority_score = min(100, (base_score + estimated_impact_pct × 0.3) × (0.5 + category_weight))
```

Where:
- `base_score` = SEVERITY_SCORES[severity] → {CRITICAL:100, HIGH:75, MEDIUM:50, LOW:25, INFO:10}
- `category_weight` = per-category weight from AdvisorConfig (0.05–0.20)

### 7.2 Health Score Formula

```
health_score = max(0, 100 - critical_count × 15 - high_count × 5 - medium_count × 1)
```

## 9. Stored Procedure Best Practices Engine

The SP analyzer inspects source code for 7 anti-patterns:

| Anti-Pattern | Detection | Severity | Impact |
|---|---|---|---|
| Missing `SET NOCOUNT ON` | Code does NOT contain `SET NOCOUNT ON` | LOW | Reduces network round-trips |
| `SELECT *` | Code contains `SELECT *` | LOW | Better plan quality |
| `CURSOR` usage | Code contains `CURSOR` | MEDIUM | 100-1000× slower than set-based |
| Dynamic `EXEC()` | Code contains `EXEC(` or `EXECUTE(` | MEDIUM | SQL injection risk, no plan reuse |
| Table variable misuse | Code contains `DECLARE @...TABLE` | MEDIUM | 1-row cardinality estimate |
| `OPTION(RECOMPILE)` overuse | Code contains `OPTION (RECOMPILE)` | LOW | Compile CPU overhead |
| Transaction w/o TRY/CATCH | Code has `BEGIN TRAN` without `TRY` | MEDIUM | Orphaned transactions |

## 11. Wait Type Mapping

The engine maps raw wait types to bottleneck categories:

| Wait Type | Category | Optimization Vector |
|---|---|---|
| `SOS_SCHEDULER_YIELD`, `THREADPOOL` | CPU | Scale up or tune queries |
| `PAGEIOLATCH_*`, `WRITELOG`, `IO_COMPLETION` | IO | Missing indexes, compression |
| `LCK_M_*` | Locking | Review transaction isolation |
| `RESOURCE_SEMAPHORE*` | Memory | Memory grants, scale up |
| `ASYNC_NETWORK_IO` | Network | Client app optimization |
| `CXPACKET`, `CXCONSUMER` | Parallelism | MAXDOP tuning |
| `LOG_RATE_GOVERNOR` | LOG_RATE | Scale up tier |
